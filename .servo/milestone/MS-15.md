## Purpose

Validate whether ReqFlow can safely use a ParadeDB PostgreSQL runtime candidate
for BM25 search while preserving pgvector, Prisma migrations, app runtime smoke
behavior, Chinese retrieval quality, and rollback to the current MS-13 runtime.

## Scope Boundary

- Use ParadeDB `pg_search` as the only BM25 runtime candidate in this milestone.
- Test runtime replacement through isolated runtime, alternate compose, or candidate profile before default runtime mutation.
- Keep the current MS-13 default runtime available as baseline and rollback target.
- Preserve native PostgreSQL FTS fallback + pgvector + RRF-style hybrid retrieval as the accepted current behavior until a later approval.
- Do not delete Docker volumes, uploads, model cache, or existing database state.
- Do not perform production data migration.
- Do not include VectorChord-BM25, `pg_textsearch`, or external search services.
- Do not evaluate embedding model quality beyond confirming pgvector/profile coexistence needed for runtime validation.

## Design Decisions To Carry Forward

1. ParadeDB is a future runtime-enablement candidate from MS-14, not active runtime behavior.
2. Runtime replacement is a database image and PostgreSQL-version compatibility problem, not only an extension flag.
3. Default runtime switch requires fdch0 approval after evidence; this milestone may recommend but not silently execute the switch.
4. Candidate compose/profile must avoid mutating accepted MS-13 default volumes and local data.
5. Chinese tokenizer choice must be explicit; `pdb.unicode default` is not automatically final.
6. Existing hybrid retrieval invariants remain: pgvector profile boundaries, no raw score addition, RRF-style rank fusion, bounded context window.

## Completion Signals

1. ParadeDB candidate image identity is pinned or a concrete pinning blocker is documented.
2. Alternate compose/profile for ParadeDB runtime is documented and validated without touching current default volumes.
3. Prisma validate, migrate deploy, seed/readiness, search extension readiness, and web runtime smoke pass or blockers are documented.
4. `pg_search` and pgvector coexistence is verified in the candidate runtime.
5. Chinese BM25 benchmark and tokenizer comparison are rerun against the candidate runtime.
6. Same-corpus comparison with current fallback/hybrid behavior is recorded.
7. Rollback to MS-13 default runtime is documented and validated.
8. Final report recommends enable/defer/reject and preserves fdch0 approval boundary.

## Acceptance Criteria

1. `npm run lint`, `npm run test`, `npm run build`, and relevant runtime smoke commands pass or have explicit not-applicable/blocker evidence.
2. Candidate runtime tests do not delete or migrate current volumes, uploads, model cache, or existing database state.
3. Extension readiness distinguishes installed/available/missing/preload-required states for `pg_search` and `vector`.
4. Prisma migration and application startup are validated against ParadeDB runtime before any enablement recommendation.
5. Chinese benchmark results include tokenizer behavior, recall/precision metrics, query latency, index build time, and EXPLAIN evidence.
6. Final docs do not claim BM25 active behavior unless a later default-runtime switch is separately approved by fdch0.

## Milestone Gate Design

- black_box: operator can start the ParadeDB candidate runtime path and run Prisma/app/search smoke commands without touching current default data.
- white_box: image identity, extension availability, Prisma migration behavior, `pg_search` index/query path, tokenizer behavior, benchmark metrics, and rollback procedure are documented.
- anti_cheat: 不允许只证明 container 启动就宣称 runtime 可切换；不允许使用 `latest` 的不可重复结果作为最终证据；不允许只跑英文或小样例；不允许把本地 PoC 性能写成生产结论；不允许默认替换 runtime。

## Developer Decision Boundary

- 默认启用 ParadeDB runtime、替换 `docker-compose.runtime.yml` 的主路径、迁移现有 volumes、删除数据/cache、生产化部署、改变检索 fusion 策略或引入外部搜索服务，需要 fdch0 单独确认。
