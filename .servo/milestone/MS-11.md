## Purpose

将 MS-10 的 hybrid retrieval 接入 AI draft flow，让 AI 草稿使用经过过滤、融合排序、上下文裁剪、Context Window Builder 和 citation 追踪的知识上下文；完成中文业务场景端到端验收、debug evidence/admin inspection surface、PostgreSQL/extension readiness gate、手工 UI 记录和 docs/operator 文档追平。

## Scope Boundary

- 不改变 AI 草稿人工确认边界，不自动创建或修改工单。
- 不向 provider 发送整库、整包原始文件或无界上下文。
- citation 必须来自 hybrid retriever 的真实命中和上下文扩展结果。
- AI draft prompt 只能使用 context builder 输出，不得绕过 hybrid retriever 直接读取知识库全文。
- Admin/debug 展示可以暴露检索证据，但不得泄露 provider secret、原始 API key 或未授权知识内容。
- docs 追平仅记录已实现事实，不伪装未完成能力。

## Completion Signals

1. AI draft request 使用 hybrid retrieval 上下文，并保留 selected knowledge bases、enabled/archived/source/snippet 过滤。
2. Citation UI 能展示真实 source、path、section、snippet 和必要的检索证据。
3. 中文业务场景从上传/解析/索引/检索/AI 草稿/表单 handoff 形成端到端验收记录。
4. PostgreSQL、pgvector、BM25/FTS fallback、Prisma migrate status 和 CI/dev/test DB readiness 有最终证据。
5. Admin/debug 展示能区分 lexical hits、vector hits、fused hits、过滤原因、最终上下文和 citation 聚合结果。
6. README/docs/operator 文档追平新架构，不保留已过期的 SQLite-only 检索流程作为当前事实。

## Acceptance Criteria

1. AI provider context 有大小上限和测试覆盖。
2. provider 缺失或失败时，基础检索和 UI 错误状态可控。
3. Citation 不伪造、不泄露禁用知识库或禁用片段。
4. Admin/debug evidence 不改变 AI 草稿结果，只用于审查和问题定位。
5. `npm run lint`、`npm run test`、`npm run build`、Prisma validate、Prisma migrate status 和 extension readiness 通过。
6. 手工 UI 流程记录包含中文业务查询、知识库选择、引用检查、debug evidence 检查、AI draft 生成和工单表单 handoff。

## Milestone Gate Design

- black_box: 用户能用中文业务问题生成带真实引用的 AI 草稿，并把选中草稿交给现有工单表单。
- white_box: hybrid retrieval context assembly、context builder cap、provider context cap、citation rendering、admin/debug evidence、DB/extension readiness 和 docs truth boundary 均有证据。
- anti_cheat: 不允许 AI 草稿绕过人工确认；不允许无界 provider context；不允许把旧 docs 写成当前事实；不允许跳过 PostgreSQL readiness；不允许 debug surface 展示越权知识内容。

## Developer Decision Boundary

- 自动创建工单、改变 provider 计费策略、引入后台 embedding 队列或生产数据迁移执行需要 fdch0 单独确认。
