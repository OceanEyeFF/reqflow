## Completion Signals

1. 管理员上传入口、权限、知识库版本、启停状态和失败回滚流程定义清楚。
2. 管理员可配置 OpenAI-compatible AI endpoint、模型、API key 策略和启用状态，并支持 localhost LMStudio/Ollama 这类无 API key 后端。
3. AI Provider 配置不向客户端暴露明文 secret；无 key 后端必须显式标记为 local/no-key 模式，避免把空 key 误当成云端配置。
4. 文档和 docs 风格 zip 上传使用私有存储，不落入 `public/uploads/`，并限制大小、类型和路径。
5. zip 解析防 path traversal，拒绝可执行/未知类型，支持 `.md`、`.txt`、`.json` 和 docs 风格目录。
6. 上传内容被解析为可追踪片段，保留来源路径、版本、导入时间和启停状态。
7. AI 生成草稿时只接收筛选后的知识片段，并能展示引用来源。
8. 管理员 UI、API 测试、安全回归和手动验收路径通过。

## Acceptance Criteria

1. 管理员可配置 OpenAI-compatible API endpoint、model 和 API key；API key 可选以支持 localhost LMStudio/Ollama。
2. 非管理员不能查看、创建、修改、启停或测试 AI Provider 配置。
3. AI Provider 配置 API 不能向客户端返回明文 API key；测试连接和草稿生成必须走服务端。
4. 管理员可上传单个文档或 docs 风格 zip 包并查看导入结果。
5. 非管理员不能上传、修改、启停或删除知识库内容。
6. 上传内容不公开暴露，不能通过路径穿越写出目标目录。
7. 知识片段有来源、版本和启停记录，AI 草稿可显示引用片段。
8. 不引入 PostgreSQL/pgvector；如需要语义检索，必须作为后续 milestone 重新评估。
9. `npm run lint`、`npm run test`、`npm run build` 通过，或 Gate 记录等价验证理由。

## Milestone Gate Design

- black_box: 管理员能配置 AI Provider、导入文档/zip，普通用户不能管理 Provider/知识库；AI 草稿可通过已启用 Provider 使用已启用知识片段。
- white_box: Provider 配置、secret 保护、localhost no-key 模式、上传安全、私有存储、解析/分块、来源版本、启停状态、检索和引用链路一致。
- anti_cheat: 不允许把 API key 暴露给客户端，不允许用空 API key 静默访问云端 Provider，不允许把上传文件放到公开目录，不允许跳过 zip 安全检查，不允许引入 PG/pgvector，不允许用固定假片段冒充导入知识库。

## Developer Decision Boundary

- 支持的文件类型、大小上限、存储位置和删除策略如超出 MVP 安全边界，需要用户确认。
- AI Provider 配置的持久化方式、API key 加密/脱敏策略、localhost endpoint allowlist、测试连接语义和默认模型策略如超出 MVP 安全边界，需要用户确认。
- PDF/DOCX/OCR、语义向量检索、跨项目知识库和生产对象存储不在默认 MS7 范围内。
- 若轻量检索无法满足需求，应 handback，而不是静默引入 PostgreSQL/pgvector 或第三方向量服务。
