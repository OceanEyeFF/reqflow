## Completion Signals

1. 当前脏状态已被分类为保留、忽略、删除、恢复或延期，并形成可复核策略矩阵。
2. 临时产物、工具缓存和本地环境文件有明确 `.gitignore` 或清理策略，`git status` 不再被低价值噪声污染。
3. 历史 worktree 与分支状态已逐项核验，已合并且无保留价值的工作区完成安全清理或留下明确 deferred 记录。
4. `AGENTS.md` 与必要 AI 协作入口反映当前项目真实工作流，未纳入版本库的 agent/tool 输出有明确边界。
5. `prisma/dev.db` 与 `prisma/dev.db-journal` 的版本策略被明确执行，避免测试或本地运行副作用反复污染主线。
6. RepoStatus、Harness 控制面和项目文档同步反映新的整洁度与 AI 适配规则。
7. 本 milestone 结束前完成独立 CodeReview，并通过 lint/test/build 或经 Gate 认可的等价验证。

## Acceptance Criteria

1. 不通过隐藏真实问题来制造表面 clean 状态；每类脏文件必须有可追溯决策。
2. 删除 worktree、恢复 tracked DB、移除工具目录等危险操作必须先核对路径、注册状态和未提交内容。
3. 不提交 `.env`、cookies、node_modules、构建缓存、Playwright MCP 日志等本地或敏感产物。
4. 所有代码仓库改动继续遵守 worktree 工作流，不直接修改 `develop` checkout。
5. 新增忽略规则不得误伤应纳入版本库的源码、文档、Harness artifact 或测试文件。
6. 文档与控制面状态在 milestone 收口时一致，下一位 AI agent 能从 repo 内规则恢复正确上下文。

## Milestone Gate Design

- black_box: `git status` 只剩明确允许的 ignored 本地产物；`npm run lint`、`npm run test`、`npm run build` 通过，或 Gate 明确记录等价验证理由。
- white_box: `.gitignore`、`AGENTS.md`、Harness 文档、worktree 清理证据和 RepoStatus 互相一致。
- anti_cheat: 不允许通过简单隐藏脏文件掩盖真实状态；所有危险删除、恢复或忽略规则变更必须有前后证据和路径核对。

## Developer Decision Boundary

- 低风险忽略规则、文档同步、临时截图/cookies 清理可在 Worktrack Gate 内自行推进。
- 删除已注册 worktree、恢复或重建 tracked `prisma/dev.db*`、移除大块 agent/tool 目录前必须在对应 worktrack 中记录证据和风险判定。
- 若发现目录承载未合并代码、未知业务数据或需要产品/架构取舍，必须 handback 给 programmer 决策。
