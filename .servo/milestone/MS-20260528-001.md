## Purpose

在 MS7 管理员项目知识库管理与导入能力已验收的基础上，扩展“多个知识库”的长期维护与 AI 查询范围选择能力：知识库按 `markdowns + 其它文档s + 文档压缩包s` 组织，zip 解压后保留原始路径层级；管理员可创建和管理多个知识库，AI 优化需求时可在对话页面选择一个或多个知识库作为检索范围。MS8 同时承接 AI 草稿回答语言选项，以及多套/拆分需求草稿能力；`docs/` 路径系统整理延期到后续 MS9。

## Completion Signals

1. 管理员可创建多个知识库，并把单文件、多文件或 zip 文档压缩包导入到指定知识库。
2. zip 解压后的原始路径层级被保留，展示、解析、启停、引用和删除时都能回溯到知识库、文件和路径。
3. 知识库遵循 `markdowns + 其它文档s + 文档压缩包s` 的组合规则，不再把 ABC 模块作为独立产品模型；跨模块内容可通过独立知识库表达。
4. 管理员可通过多选、全选、反选后删除选中知识内容，替代“旧版本全清”这类过于武断的操作。
5. AI 草稿页面允许用户选择一个或多个知识库作为查询范围；暂不做上下文自动选择。
6. AI 草稿生成支持回答语言选项，至少能通过显式中文选项约束回答语言。
7. 当用户描述自然需要拆分时，AI 草稿生成最多输出 3 套候选草稿；上限通过变量配置。
8. 多草稿确认流只允许用户选择一个草稿进入创建工单表单，不允许一次同时审批多个工单草稿。
9. MS7 既有上传、解析、检索、引用、Provider 配置与权限安全回归保持通过。
10. `npm run lint`、`npm run test`、`npm run build` 通过，或 Gate 记录等价验证理由。

## Acceptance Criteria

1. 管理员可创建多个知识库，并把文件、多个文件或 zip 导入到指定知识库；导入结果能展示文件路径、解析状态、片段数量和失败原因。
2. 非管理员不能创建、修改、删除、批量删除或重组知识库内容。
3. 多知识库模型与现有来源、版本、启停、片段引用链路兼容，不破坏 MS7 已完成数据。
4. 删除操作只影响管理员明确勾选的知识内容；多选、全选、反选都必须有明确确认边界。
5. AI 草稿页面可选择一个或多个知识库作为检索范围；系统不会暂时根据上下文自动切换知识库。
6. AI 草稿生成只使用所选知识库中已启用的知识片段，引用来源能回溯到对应知识库、文件、路径和版本。
7. 删除、禁用或取消选择知识库后，AI 草稿不会继续引用已删除、已禁用或范围外片段。
8. 不引入 PostgreSQL/pgvector；如需要语义检索或跨项目知识库，应作为后续 milestone 重新评估。
9. AI 草稿页面提供 `跟随用户输入 / 中文 / 英文` 三档回答语言选择；该选项不能破坏现有草稿 schema。
10. AI 多草稿/拆分能力一次最多生成 3 套候选草稿，上限由变量控制；用户只能选择一套进入创建工单表单。
