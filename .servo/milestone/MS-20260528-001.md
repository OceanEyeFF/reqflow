## Purpose

在 MS7 管理员项目知识库管理与导入能力基础上，扩展知识库的长期维护与业务范围选择能力：支持多文件上传作为文件夹/批次管理，建立知识库分组与文件夹模型，提供旧版本全清与批量删除能力，支持多个开发环境/模块（ABC 模块）切换，并让 AI 草稿生成按当前模块选择知识库检索范围。MS8 不替换 MS7 的补缺与最终验收流程，MS7 final acceptance 仍由用户决定。

## Completion Signals

1. 管理员可一次上传多个文件，并以文件夹/批次形式查看、解析、启停和追踪来源路径。
2. 知识库具备分组/文件夹模型，支持按项目、环境或模块组织资料，并保留权限边界与来源版本信息。
3. 管理员可对旧版本知识库执行全清或批量删除，删除行为有明确确认、防误删边界和私有存储清理策略。
4. 系统支持多个开发环境/模块配置，至少能表达 ABC 模块，并在管理端或业务入口中切换当前模块上下文。
5. AI 草稿生成能按当前模块/环境选择知识库检索范围，不会混用未选模块或已禁用/已删除知识片段。
6. MS7 既有上传、解析、检索、引用、Provider 配置与权限安全回归保持通过。
7. `npm run lint`、`npm run test`、`npm run build` 通过，或 Gate 记录等价验证理由。

## Acceptance Criteria

1. 管理员可上传多个文件并作为同一文件夹/批次导入；导入结果能展示文件层级、解析状态、片段数量和失败原因。
2. 非管理员不能创建、修改、删除、批量删除、全清或重组知识库文件夹/分组。
3. 知识库分组/文件夹与现有来源、版本、启停、片段引用链路兼容，不破坏 MS7 已完成数据。
4. 批量删除和旧版本全清只影响被明确选中的范围，不能误删其他模块、其他文件夹或当前启用资料。
5. 多环境/模块切换至少支持 ABC 模块配置，并能被 AI 草稿流程读取为检索范围条件。
6. AI 草稿生成只使用当前模块允许的已启用知识片段，引用来源能回溯到对应文件夹/文件/版本。
7. 删除、禁用或切换模块后，AI 草稿不会继续引用已删除、已禁用或范围外片段。
8. 不引入 PostgreSQL/pgvector；如需要语义检索或跨项目知识库，应作为后续 milestone 重新评估。
9. MS7 final acceptance 不由 MS8 自动完成或覆盖，仍需用户明确验收。

## Milestone Gate Design

- black_box: 管理员能按文件夹/分组管理多文件知识库，并在 AI 草稿中选择对应模块范围。
- white_box: 文件夹模型、删除/清理、模块范围和现有 source/version/snippet/citation 链路一致。
- anti_cheat: 不允许跨模块混用知识片段，不允许删除未选范围，不允许绕过管理员权限，不允许静默引入 pgvector/embedding。

## Developer Decision Boundary

- 文件夹/分组是否允许嵌套、多级层级深度、重命名/移动语义超出 MVP 时，需要用户确认。
- “旧版本全清”是物理删除、软删除、归档还是仅禁用，涉及不可恢复数据清理时需要用户确认。
- ABC 模块的来源、命名、默认模块、用户可见切换入口和跨模块共享知识策略需要用户确认。
- AI 草稿范围选择若需要复杂 RBAC、跨项目知识库、向量检索、对象存储或后台队列，不在默认 MS8 范围内。
- 不得静默改变 MS7 acceptance 状态；MS7 是否最终验收由用户决定。
