## Purpose

系统性提升管理员知识库在中文业务流程、物料规则、审批限制和中英文术语混合场景下的召回质量。该 milestone 在现有轻量级检索基础上引入中文归一化、n-gram/领域词典、结构化索引、可选 AI 入库增强和文件级上下文扩展，使 AI 草稿能获得可追溯、可解释、不过量的知识上下文。

## Scope Boundary

- 保持现有 Next.js 16 + Prisma 5 + SQLite 技术栈。
- 不默认引入 PostgreSQL、pgvector、外部向量数据库或不可控常驻检索服务。
- AI API 可用于入库时的关键词/实体/规则摘要增强或查询改写，但不得替代权限过滤、知识库 enabled 过滤和人工确认边界。
- 不向 provider 默认发送整包原始文件；以命中片段、相邻片段、文件标题/路径和结构化摘要为主。
- 保持 AI 输出只能作为草稿/建议，不能直接创建或修改工单。

## Completion Signals

1. 给定“外仓部分物料→内仓送检限制使用放行审批”样本文本和同类中文流程知识，系统能通过业务查询稳定召回相关知识。
2. 检索层支持中文文本归一化、常见符号归一化、中文 n-gram、领域词典/缩写和基础中英文混合关键词匹配。
3. 入库后的知识片段具备可检索的结构化字段，例如关键词、实体、流程步骤、适用/不适用规则或摘要。
4. AI 增强若启用，只作为入库/查询辅助；失败时基础检索仍可工作，且 provider secret 不进入客户端。
5. 命中片段能扩展到相邻 chunk 或同文件聚合上下文，并保留 source、path、section、snippet 可追溯信息。
6. AI 草稿使用增强后的检索上下文，但仍遵守知识库 enabled/archived 过滤、知识库选择范围、引用显示和人工确认边界。
7. 最终验收包含固定查询集的召回验证、误召回审查、自动化测试、Prisma/数据库 readiness 和手工 UI 流程记录。

## Acceptance Criteria

1. 当前 `includes` 式中文漏召回样例被自动化测试覆盖，并在增强后通过。
2. 不选择已禁用/归档知识库，不检索禁用 source/snippet，不绕过现有知识库范围选择。
3. 结构化索引字段可通过 migration 安全新增，不删除已有 schema 字段或破坏旧知识片段。
4. AI 关键词/摘要增强具备开关、错误降级和测试替身；缺少 provider 配置时不阻塞基础导入或基础检索。
5. 文件级上下文扩展不会无界发送整份大文件给 AI provider；上下文大小有上限并可测试。
6. 引用面板能显示命中文件/片段来源，避免伪造引用。
7. `npm run lint`、`npm run test`、`npm run build` 通过，且 Milestone DB Readiness Gate 通过。

## Milestone Gate Design

- black_box: 用户用中文业务问题查询知识库时，能命中相关流程/规则片段，并在 AI 草稿引用中看到可追溯来源。
- white_box: 检索得分、结构化索引、AI 入库增强、文件级扩展和 provider 上下文裁剪均有测试证据。
- anti_cheat: 不允许用“发送全部知识给 AI”掩盖检索问题；不允许绕过知识库选择/禁用过滤；不允许无界 provider 上下文；不允许 AI 增强失败导致基础知识导入不可用。

## Developer Decision Boundary

- 引入 PostgreSQL、pgvector、外部向量数据库、第三方搜索服务或常驻索引服务需要单独确认。
- 默认发送整份文件、批量重建全部历史知识库、变更 provider 计费/调用策略或新增不可控后台任务需要单独确认。
- 如果评测语料显示需要语义向量检索，应先产出架构评估 worktrack，再决定是否升级技术栈。
