## Purpose

Implement ParadeDB `pg_search` as ReqFlow's default local PostgreSQL runtime
using fresh validation data, wire the app lexical lane to `pg_search`, preserve
native FTS fallback, and validate runtime/config rollback without migrating old
MS-13 development data.

## Scope Boundary

- Switch the default local PostgreSQL runtime path toward ParadeDB `pg_search`
  only through approved MS-17 worktracks and gates.
- Use fresh ParadeDB volume/data as the MS-17 validation baseline.
- Design or update seed/test corpus data for runtime and retrieval validation.
- Add safe `pg_search` schema/index migration behavior for a fresh database.
- Implement app lexical retrieval engine gating for ParadeDB and native FTS
  fallback.
- Validate hybrid retrieval with actual ParadeDB lexical lane while preserving
  RRF-style fusion and raw-score separation.
- Validate runtime/config rollback to the previous MS-13-style path without
  claiming old-data restoration.
- Do not migrate or delete old MS-13 volumes, uploads, model cache, or database
  state.
- Do not make production deployment choices in this milestone.

## Design Decisions To Carry Forward

1. MS-16 selected ParadeDB `pg_search` as the intended future default runtime
   direction.
2. MS-17 uses fresh ParadeDB data as the validation baseline.
3. MS-13 old development data is not an MS-17 migration or compatibility target.
4. Old local volumes/data must remain untouched unless fdch0 separately approves
   destructive cleanup.
5. MS-13 remains a runtime/config rollback reference, not an old-data rollback
   acceptance target.
6. Runtime switch alone is insufficient; app lexical retrieval must use
   `pg_search` before BM25 product behavior can be claimed.
7. Native FTS fallback remains required as an explicit fallback path.
8. Hybrid fusion must preserve RRF-style rank fusion and must not add raw
   BM25/vector scores.

## Completion Signals

1. Default local runtime starts with ParadeDB and a fresh validation database.
2. `pg_search` and `vector` readiness are verified in the default runtime path.
3. Prisma validate, migrate deploy, seed, and web smoke pass against the fresh
   ParadeDB runtime.
4. `pg_search` schema/index migration behavior is safe for fresh databases and
   explicitly gated when extension readiness is absent.
5. App lexical retrieval uses ParadeDB `pg_search` when available and native FTS
   fallback when required.
6. Hybrid retrieval validation proves actual ParadeDB lexical lane participation
   with RRF-style fusion and citation behavior.
7. New test corpus and Chinese/product search quality gates pass or document
   blockers and tokenizer caveats.
8. Runtime/config rollback is documented and validated without old-data
   restoration claims.
9. Final handback states whether ParadeDB is ready as the accepted default local
   runtime.

## Acceptance Criteria

1. No MS-13 old volume/data migration or compatibility validation is required or
   claimed.
2. No Docker volume, upload, model cache, or database state is deleted as part of
   milestone success.
3. Default runtime implementation is covered by compose config, readiness,
   Prisma, seed, web smoke, and rollback evidence.
4. App retrieval evidence demonstrates real `pg_search` lexical-lane behavior,
   not only candidate SQL probes.
5. Retrieval validation preserves permission filters, citations, RRF fusion, and
   raw-score separation.
6. Chinese tokenizer/product corpus caveats are explicit and do not overclaim
   production quality.
7. `npm run lint`, `npm run test`, and `npm run build` pass or blockers are
   documented with recovery worktracks.
8. MS-17 final acceptance remains fdch0-only.

## Milestone Gate Design

- black_box: a developer/operator can start ReqFlow's default local runtime on
  fresh ParadeDB data and run product retrieval smoke without manually choosing
  the old runtime.
- white_box: evidence proves `pg_search` readiness, index/migration behavior,
  app lexical-lane selection, RRF fusion, and rollback boundaries.
- anti_cheat: do not count isolated ParadeDB candidate probes as app behavior;
  do not claim old data migration; do not delete or reuse MS-13 volumes as proof;
  do not claim production readiness from local benchmark data.
