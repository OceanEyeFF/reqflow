## Purpose

## Completion Signals

1. 管理员可以编辑知识库名称、描述和启用状态；内部 slug / 系统标识保持唯一且不可修改，第一版建议使用较短的 hash-like 生成值防止碰撞。
2. 知识库支持禁用/归档语义；禁用和归档在用户层面等价，普通用户不可感知该知识库存在，且不参与 scoped retrieval。
3. 第一版不做有内容知识库的物理删除；如后续需要删除，只允许空知识库或另开明确确认边界。
4. 默认知识库必须保留，不允许删除；禁用/归档知识库后不允许新增来源，允许查看、恢复和编辑元信息，不允许清理内容，除非先恢复为非归档知识库。
5. AI 追问必须固定按三个方向组织：知识库依据、应用场景、需求细节；每个方向最多 5 个问题。
6. 多方向追问仍必须保持人工确认边界，不得直接创建或修改工单。
7. 追问方向应在前端以固定标签“知识库依据 / 应用场景 / 需求细节”呈现；用户使用统一回答区回答。
8. `npm run lint`、`npm run test`、`npm run build` 通过，且 Milestone DB Readiness Gate 通过。

## Acceptance Criteria

1. 管理员能从知识库管理界面编辑知识库基本信息和启用/归档状态。
2. 禁用/归档知识库后，上传目标、AI 页面选择项和检索结果都遵循同一 enabled 语义；禁用/归档知识库不允许新增来源，也不允许清理内容，除非先恢复。
3. 有来源内容的知识库不会被误物理删除；默认知识库不可删除；内部 slug / 系统标识唯一且不可改。
4. AI 追问结果包含固定方向信息，且 UI 按“知识库依据 / 应用场景 / 需求细节”展示，每个方向最多 5 个问题。
5. 追问方向不会破坏现有 clarification response 兼容性；旧字段仍可被安全处理。
6. 多方向追问阶段只收集澄清；草稿阶段继续最多生成 3 个候选/拆分草稿，且仍只能选择一个交给工单表单。
7. Prisma schema/migration、当前开发数据库状态、管理员知识库 API readiness 必须在最终 handback 前通过。
8. 最终验收必须包含手工 UI 流程记录。

## Milestone Gate Design

- black_box: 管理员能维护知识库生命周期；用户能看到多方向 AI 追问并继续生成草稿。
- white_box: enabled/archived 语义在 admin UI、upload target、public bases API、retrieval 和 citations 中一致；内部 slug / 系统标识唯一且不可改；clarification schema 兼容旧调用。
- anti_cheat: 不允许误删有内容知识库；不允许删除默认知识库；不允许禁用后新增或清理来源；不允许禁用后继续被 AI 检索；不允许多方向追问绕过人工确认；不允许跳过 Milestone DB Readiness Gate 或手工 UI 流程记录。

## Developer Decision Boundary

- 物理删除非空知识库、删除默认知识库、批量迁移来源到其它知识库、重写 slug 策略、为禁用/归档知识库清理内容、自动选择追问方向或引入复杂对话状态机，需要单独确认。
- 如果多方向追问需要改变 provider schema 或 UI 交互较大，应优先保持兼容扩展，不做破坏性 schema 替换。
- 已确认的问题仅授权细化 MS8 addendum 范围；初始化 WT-20260528-064 仍需 fdch0 明确请求。
