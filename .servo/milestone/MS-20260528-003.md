## Purpose

在 MS8 的多知识库与 AI 草稿范围能力稳定后，补齐两个自然延伸：管理员对知识库本身的生命周期管理，以及 AI 追问从多个方向组织问题的能力。该 addendum 不改变 MS8 已确认的“知识库可选择、AI 范围过滤、单草稿确认边界”，而是在其上提升可维护性和对话质量。

## Completion Signals

1. 管理员可以编辑知识库名称、描述和启用状态；slug 或系统标识的修改必须有兼容边界。
2. 知识库支持禁用/归档语义，禁用后不出现在普通用户 AI 选择范围中，不参与 scoped retrieval。
3. 第一版不做有内容知识库的物理删除；如后续需要删除，只允许空知识库或另开明确确认边界。
4. 默认知识库必须保留，不能被删除或破坏性禁用到导致历史来源不可管理。
5. AI 追问可以按方向组织，至少覆盖：知识库/参考资料角度、应用场景角度、具体需求细节角度。
6. 多方向追问仍必须保持人工确认边界，不得直接创建或修改工单。
7. 追问方向应在前端可读地呈现，用户可以理解每个问题为什么被问。
8. `npm run lint`、`npm run test`、`npm run build` 通过，且 Milestone DB Readiness Gate 通过。

## Acceptance Criteria

1. 管理员能从知识库管理界面编辑知识库基本信息和启用/归档状态。
2. 禁用/归档知识库后，上传目标、AI 页面选择项和检索结果都遵循同一 enabled 语义。
3. 有来源内容的知识库不会被误物理删除；默认知识库有明确保护。
4. AI 追问结果包含方向信息，且 UI 能区分或展示方向，例如“知识库依据 / 应用场景 / 需求细节”。
5. 追问方向不会破坏现有 clarification response 兼容性；旧字段仍可被安全处理。
6. 多方向追问后生成草稿仍走现有单选人工确认流程。
7. Prisma schema/migration、当前开发数据库状态、管理员知识库 API readiness 必须在最终 handback 前通过。

## Milestone Gate Design

- black_box: 管理员能维护知识库生命周期；用户能看到多方向 AI 追问并继续生成草稿。
- white_box: enabled/archived 语义在 admin UI、upload target、public bases API、retrieval 和 citations 中一致； clarification schema 兼容旧调用。
- anti_cheat: 不允许误删有内容知识库；不允许禁用后继续被 AI 检索；不允许多方向追问绕过人工确认；不允许跳过 Milestone DB Readiness Gate。

## Developer Decision Boundary

- 物理删除非空知识库、批量迁移来源到其它知识库、重写 slug 策略、自动选择追问方向或引入复杂对话状态机，需要单独确认。
- 如果多方向追问需要改变 provider schema 或 UI 交互较大，应优先保持兼容扩展，不做破坏性 schema 替换。
