## Purpose

把当前分散的本地运行方式整理为可复现 Docker Compose runtime bundle：web、PostgreSQL/pgvector、optional embedding sidecar、migrate/seed/indexing/probe 辅助流程和 operator runbook 能一起启动、验证和停止。

该 milestone 不把开源 embedding 模型权重打进主 Next.js app image；默认采用 sidecar/runtime bundle 方式降低主应用镜像体积、部署耦合和回滚风险。

## Scope Boundary

- 不把 embedding 模型权重复制进主 web image。
- 不默认启用生产级 embedding indexing 队列，除非 MS-12 或本 milestone 内的独立 Worktrack 验证通过。
- 不把 BM25 作为 PostgreSQL core 或必然可用能力；如果 runtime image 不支持合适的 BM25 extension，仍必须保留 native PostgreSQL FTS fallback。
- 不执行生产数据迁移，不删除本地 volume 或模型 cache，除非 fdch0 单独批准。
- 不改变 AI provider secret 管理策略；任何 secret 仍必须保持服务端边界。

## Design Decisions To Carry Forward

1. Runtime bundle should provide one documented start path for local product inspection without requiring users to remember separate DB/model/app commands.
2. The web container should stay small and model-agnostic; embedding inference belongs in an optional sidecar.
3. PostgreSQL must include pgvector readiness. BM25 support is desirable but optional, and must come from a verified extension/runtime package rather than PostgreSQL core.
4. Migrations and seed must be explicit, repeatable, and safe against accidental production DATABASE_URL use.
5. Local cache/volume cleanup must be a separate explicit operator action because model cache and database volumes can contain useful state.

## Completion Signals

1. A local operator can start the runtime bundle and open the login page from a documented URL.
2. PostgreSQL migration/seed/readiness checks run through documented commands.
3. Optional embedding sidecar can be started, probed, and stopped without changing the web image.
4. Runtime smoke validates web HTTP, Prisma/PG read path, and optional embedding inference.
5. BM25 extension runtime feasibility is either validated in the chosen image or explicitly deferred with fallback instructions.
6. README/operator docs explain start, stop, logs, readiness, probe, and cache/volume boundaries.

## Acceptance Criteria

1. `docker compose` runtime path works on the target local environment with PostgreSQL and web.
2. Optional embedding sidecar probe records model, dimensions, latency, memory, and cache behavior.
3. `npm run lint`, `npm run test`, `npm run build`, PostgreSQL readiness, search extension readiness, and runtime smoke pass or have explicit not-applicable evidence.
4. No command silently deletes volumes, model cache, uploads, or database state.
5. Docs do not claim production readiness; cloud deployment, backup/restore, secrets, and production migration remain separate approval boundaries.

## Milestone Gate Design

- black_box: 用户能通过 documented Docker Compose path 启动网页、连接 PostgreSQL，并可选调用 embedding sidecar。
- white_box: Dockerfile/compose/env/migrate/seed/readiness/probe/logging/runbook 均有证据，BM25 fallback boundary 清晰。
- anti_cheat: 不允许只在宿主机 npm dev 成功却宣称 Docker bundle 完成；不允许把模型塞进主 app image；不允许把 PostgreSQL core/native FTS 或 BM25 extension 不可用环境写成 BM25 已启用。

## Developer Decision Boundary

- 删除 volumes/cache、生产化 Docker 部署、启用 BM25 extension 默认 runtime、改变 secret 管理或引入后台 indexing worker 需要 fdch0 单独确认。
