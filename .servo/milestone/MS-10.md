## Purpose

在 MS-9 建立的 PostgreSQL 与 extension 基线之上，实现知识库 hybrid retrieval：lexical BM25/FTS 召回、embedding + pgvector 语义召回、RRF/加权融合排序、权限过滤、相邻 chunk/文件级上下文扩展，以及可解释 score/citation 输出。

## Scope Boundary

- 以 PostgreSQL 为目标数据库。
- 优先使用 MS-9 确认的 BM25 方案；若不可用，使用 MS-9 确认的 FTS fallback。
- embedding 生成必须受 provider secret/server boundary 保护，并可在测试中使用 deterministic fake。
- embedding 生成必须绑定 active SearchIndexProfile；同一检索只比较同一 profile 内的 vectors。
- 检索必须始终遵守 knowledge base enabled/archived、source enabled/status、snippet enabled 和用户选择范围。
- provider context 必须有上限，不允许发送整库或整包原始文件。

## Completion Signals

1. 知识片段具备可检索 index schema，支持 lexical 与 vector 双路召回。
2. KnowledgeEmbedding 记录 profileId、model、dimensions、contentHash 和状态；换模型或维度不会静默复用旧向量。
3. 中文业务查询能通过 lexical/vector/fusion 命中相关知识，而不是依赖简单 includes。
4. 检索输出包含可审查的 score breakdown 或 debug evidence。
5. 禁用/归档知识库、禁用 source/snippet、未选择知识库均不会被召回。
6. 命中结果能扩展相邻 chunk 或文件级上下文，并保留 source/path/section/snippet citation。

## Acceptance Criteria

1. Hybrid retrieval 测试覆盖 lexical-only、vector-only、fusion、误召回和权限过滤。
2. embedding provider 失败时有可控降级，不破坏 lexical 检索。
3. active SearchIndexProfile 缺失、building、deprecated 或 dimensions mismatch 时，vector retrieval 不得静默运行。
4. 上下文扩展有大小上限并可测试。
5. 不伪造 citation，不返回未命中的 source 作为证据。
6. `npm run lint`、`npm run test`、`npm run build` 和 PostgreSQL DB readiness 通过。

## Milestone Gate Design

- black_box: 用户输入中文业务问题时，系统稳定召回相关知识片段并显示可追溯引用。
- white_box: BM25/FTS、pgvector、SearchIndexProfile、embedding status、fusion、filter、context expansion 均有测试证据。
- anti_cheat: 不允许整库塞给 AI；不允许绕过过滤；不允许只靠 vector 隐藏 lexical 漏召回；不允许不可解释排序。

## Developer Decision Boundary

- 变更 embedding provider 计费策略、引入后台批处理队列、使用外部搜索服务或批量重建生产知识库需要 fdch0 单独确认。
